1. 프로젝트 개요

목적: 다수 참여자가 각자의 메일 계정으로 특정 기관에 항의 메일을 보내는 캠페인 웹페이지. 수신 측 필터의 일괄 스팸 분류 회피가 핵심 요구.

확정된 설계 원칙

  • 원칙1참여자 1명당 기관 1곳 = 1통. to/cc에 여러 기관 동시 발송 금지 (스팸 점수 직격 + "여러 군데 돌린 성명서" 인식으로 효과 감소 — 사용자 확인 사항)
  • 원칙2기관마다 내용(제목·본문)이 달라야 함 — 해시 매칭 기반 일괄 분류 회피
  • 원칙3폴백은 클립보드만. 웹메일 딥링크는 실서비스 미포함 (조사 결과 모바일 전부 실패)

핵심 결론

  1. mailto: 전 환경 완전동작 — 제목·복수줄 본문·bcc·4000자·줄바꿈 양식 모두 무손실. mailto 단독 사용 가능
  2. 웹메일 딥링크는 데스크톱(로그인 상태)에서만 동작 → 실서비스 제외 확정
  3. 네이버 메일은 전 기기 실패 — 외부 파라미터 주입 미지원. 폴백에서도 제외
  4. 줄바꿈은 %0D%0A 통일 (표준 준수, 전 기기 검증)
  5. iOS에서 mailto·클립보드는 클릭 핸들러 안에서 동기 시작 필수 (window.location.href 직접 할당)

4. 현재 구현 상태 (테스트 버전 배포됨)

/root/protest-page/index.html — 현재 Pages 루트에 배포된 테스트 페이지:

  • 이름 + 한마디 입력 → 참여하겠습니다 버튼
  • 수신처 리스트 표시 → 기관별 메일 쓰기 버튼 → mailto 오픈
  • 기관마다 템플릿 다각화: 제목 풀 5종 × 본문 프레임 5종 무작위 조합, 이름·한마디가 {name}/{msg}/{msg-s} 자리표시자로 삽입
  • 현재 수신처 = 예시 기관 A/B/C (더미), {issue} = "이번 사안" 더미

5. 다음 작업 — 세션 이어가기

대기 중인 사용자 입력

  1. 실제 항의 대상 기관명 + 이메일 주소 목록
  2. 항의 내용/요구사항 원문

수령 후 작업 순서

  1. SUBJ_POOL/BODY_FRAMES를 실제 내용으로 작성 — 문장 구조·어휘·길이가 실제로 달라야 함 (단순 단어 치환은 해시 우회 불가)
  2. DESTS 교체, ISSUE 설정
  3. 로컬 확인 → hermes-docs push → curl 200 확인
  4. 사용자에게 URL 전달, 실기기 최종 확인 요청 (입력→버튼→메일앱 오픈)

스팸 회피 설계 원칙 (구현됨): 기관별 프레임 구조 자체가 다른 템플릿 / 참여자 이름·한마디 개인화 / "자기 경험 한 줄 추가" 유도 / "며칠에 걸쳐 분산 발송" 유도 / 링크·첨부 최소화
